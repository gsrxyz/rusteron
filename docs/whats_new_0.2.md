# What's new in 0.2

0.2 is a breaking release. The [rusteron-client README](https://github.com/gsrxyz/rusteron/blob/main/rusteron-client/README.md#general-patterns) has a deeper write-up. See also the [migration guide](https://github.com/gsrxyz/rusteron/blob/main/docs/migrating_0.1.168_to_0.2.md).

- **Deferred close.** `aeron.close()` no longer frees child resources immediately (the 0.1.x behaviour was a use-after-free). Close is deferred until the last reference drops, and drop order is arbitrary. `unsafe close_now()` forces immediate teardown.
- **Reference-counted handlers.** `Handler::leak()`/`release()` are gone; `Handler::new()` is `Arc`-backed and freed when the last clone drops. Retained-callback setters take the value (closure or trait impl) and return the `Handler`. `Handlers::NONE` covers "no callback".
- **Typed errors.** `offer`/`try_claim` return `Result<i64, AeronOfferError>` with `is_retryable()`. `AeronCError` construction is allocation-free (never reads `aeron_errmsg()`); `capture_errmsg()` opts into attaching the message. Archive control ops return `Result<_, AeronArchiveError>` (`From` keeps `?` working).
- **Hot path.** `offer_parts(&[&header, &payload])` publishes several buffers as one message with no intermediate Vec; C-string args follow the `c""`/`cformat!`/reuse pattern ([C strings without hidden allocations](https://github.com/gsrxyz/rusteron/blob/main/README.md#c-strings-without-hidden-allocations)).
- **After 0.2.13, callback panics no longer abort.** Poll handler panics unwind to the caller of `poll`; other callbacks catch the panic and raise it once C returns, or log it if C fires them later (see [Panics in callbacks](https://github.com/gsrxyz/rusteron/blob/main/README.md#panics-in-callbacks)). The fragment, controlled and block handler typedefs and the 9 subscription, image and replay-merge poll functions are `extern "C-unwind"`; a raw handler passed to them must be declared `unsafe extern "C-unwind" fn` (the compiler rejects `extern "C"`). Setters that store another wrapper, such as `AeronArchiveContext::set_aeron()`, now keep it alive.
- **After 0.2.16, callback arguments are borrowed.** Callbacks receive `&AeronHeader`, `&AeronImage`, `&AeronArchiveRecordingDescriptor` and so on. Safe code can no longer keep a struct that C frees when the callback returns. Structs that only exist inside callbacks lose `Clone` and the safe `From` impls, and `clone_struct` is `unsafe` on structs with pointer fields (#73, see [Callback arguments are borrowed](https://github.com/gsrxyz/rusteron/blob/main/rusteron-client/README.md#callback-arguments-are-borrowed)).
- **After 0.2.10, handles are `Send` only under `multi-threaded`.** Up to 0.2.10, publication, subscription, counter and counters-reader handles were `Send` without it, which was unsound because each shares its client's `Rc` reference count. Code that moves one to another thread now gives that thread its own client (`Aeron::connect_dir`) or enables `multi-threaded`.
- **Convenience.** `Aeron::connect_dir`, `AeronDriver::launch_embedded_guard` (RAII), `ChannelUri::add_session_id`, `AeronUriStringBuilder::ipc()/udp()`, retained-image accessors, direct constant getters, and ported samples (basic_publisher/subscriber, ping/pong, file transfer, MDS, request/response).
